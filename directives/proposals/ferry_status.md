# B3. 우도·가파도·마라도 배편 운항 정보 출처 조사 제안서 (`ferry_status.md`)

> **[운영자 결정 반영 (2026-10-29)]**
> - 공공데이터포털에서 연안여객선 API는 폐기/이관되어 사용하지 않기로 확정했습니다(중국인 관광객의 대부분이 방문하는 **우도**는 애초에 연안여객선이 아닌 '도선'이라 해당 API에 포함되지도 않음).
> - 따라서 코드 반영 시 외부 여객선 API를 호출하지 말고, 본 문서 **4절(기상청 해상 풍랑특보 자동 감지 + 브리핑 카드 하단 컨트롤 바 수동 토글 `자동 / 정상운항 / 확인필요 / 전면통제` + 매표소 안내)** 방식으로만 구현할 것.

## 1. 조사 개요 및 핵심 요약

- **목적**: 기상특보 브리핑 카드(`src/js/features/brief-card.js`의 `ALERT` 탭)에 항공편 결항/지연 현황과 함께 **"오늘 우도·가파도·마라도 배편 운항 여부"**를 자동으로 표시할 수 있는지 공식 API·공개 웹페이지·전화 안내 출처를 전수 조사.
- **핵심 결론 (해운법 여객선 vs 유도선 사업법 도선의 결정적 차이)**:
  1. **가파도·마라도 (운진항 출발)**는 **「해운법」상 내항정기여객선**으로, **한국해양교통안전공단(KOMSA) 공식 Open API (`apis.data.go.kr/B554035/...`)** 및 선사 홈페이지(`wonderfulis.co.kr`)를 통해 **완전 자동화 조회가 가능**합니다.
  2. 반면 **우도 (성산포항·종달항 출발)** 및 **마라도 (송악산항 출발)** 배편은 여객선이 아니라 **「유선 및 도선 사업법」상 '도선(渡船)'** 면허 사업장입니다. 따라서 **한국해양교통안전공단(KOMSA) API 및 PATIS 시스템에 아예 포함되지 않으며**, 정부 공공데이터 API가 존재하지 않습니다.
  3. 따라서 특보 카드에 넣을 때는 **① 가파도·마라도(운진항)는 KOMSA 공공데이터 API로 자동 조회**하고, **② 우도(성산포항)는 우도도항선 모바일 공지 페이지 스크래핑 + 해상 기상특보(제주도동부앞바다 풍랑특보 시 100% 통제) 하이브리드 판정(또는 브리핑 카드 하단에 운영자 원클릭 토글 `정상 / 통제 / 미정` 제공)** 방식을 결합하는 것이 가장 정확하고 안전합니다.

## 3. 출처별 상세 기술 명세

### 3.1 [공식 Open API] 한국해양교통안전공단(KOMSA) 연안여객선 API (가파도·마라도 운진항)

공공데이터포털(`data.go.kr`)에서 기관코드 **`B554035`**로 제공되며, `functions/api/public-data.js`의 `ALLOWED_DOMAINS`에 이미 등록된 **`apis.data.go.kr`** 도메인을 사용하므로 프록시 화이트리스트 수정 없이 즉시 연동할 수 있습니다.

1. **한국해양교통안전공단_여객선 운항상태 정보 (`ferry-route-info-v4`)**
   - **엔드포인트**: `https://apis.data.go.kr/B554035/ferry-route-info-v4/get-ferry-route-info-v4`
   - **주요 응답 항목**:
     - 여객선명(`psnshpNm`, 예: 블루레이1호, 블루레이2호, 가파도호 등)
     - 면허항로명 / 운항항로명(`oprtRtNm`, 예: `모슬포-가파도`, `모슬포-마라`)
     - 출발일자 및 시각
     - **운항상태**: `정상` / `통제`(기상악화 결항) / `휴항` 등
2. **한국해양교통안전공단_운항 스케줄 정보 (`oprt-schd-info-v2`)**
   - **엔드포인트**: `https://apis.data.go.kr/B554035/oprt-schd-info-v2/get-oprt-schd-info-v2`
   - **주요 응답 항목**: 출항지명(`모슬포`), 운항항로명, 출항시각, **통제사유**(기상악화 등)
3. **한국해양교통안전공단_내일의 운항예보 (`tmr-forecast` / `tmr-forecastnew`)**
   - **엔드포인트**: `https://apis.data.go.kr/B554035/tmr-forecast/get-tmr-forecast`
   - **특징**: 전날 저녁에 다음 날 항로별 운항 가능 여부(원활/주의/통제예상)를 미리 발표하므로 저녁 6시 이후 브리핑 카드 생성 시 유용합니다.
4. **KOMSA 대국민 웹 조회 페이지 (PATIS)**:
   - URL: `https://www.komsa.or.kr/prog/psnshpOprtInfo/kor/sub04_0102/list.do` (실시간 운항현황)
   - 제주 지사(`제주`) 선택 시 모슬포(운진항) ↔ 가파도·마라도 항로 상태 확인 가능.

> **미확인 표시**: `B554035/ferry-route-info-v4` API의 정확한 쿼리 파라미터명(예: 항로 필터 파라미터 대소문자 및 날짜 형식 `YYYYMMDD` vs `YYYY-MM-DD`)은 공공데이터포털에서 활용신청 후 다운로드 가능한 명세서에서 최종 확인이 필요합니다(**미확인**).

### 3.2 [공개 웹페이지] 선사별 공식 홈페이지

#### ① 우도 도항선 (`우도가는배`)
- **공식 모바일 공지 URL**: `http://udoboat.smart9.net/m/` (PC 리디렉션: `http://udoship.com`)
- **운영 특성**:
  - 우도 도항선은 온라인 사전 예약을 받지 않고 **100% 현장 발권**으로 운영됩니다.
  - 기상 악화 시 당일 아침 **06:30~07:00경** 첫배 출항 전 선장 및 해경 협의를 거쳐 운항/전면결항/조기종료 여부를 결정합니다.
  - 홈페이지 팝업 또는 공지사항 게시판에 `"○월 ○일 기상악화(풍랑주의보)로 인하여 전항로 결항합니다"` 형태로 텍스트가 올라오지만, **정형화된 상태 배지(정상/결항) DOM 요소가 따로 있지 않고 자유 형식 게시글**로 올라오는 한계가 있습니다.
  - 또한 `http://` (비보안 HTTP) 구형 호스팅(`smart9.net`)을 사용합니다.

#### ② 가파도·마라도 정기여객선 (`아름다운섬나라` — 운진항)
- **공식 URL**: `https://www.wonderfulis.co.kr`
- **실시간 운항정보 메뉴**: 메인 화면 상단 배너 및 `[운항안내 및 예매] → [실시간 운항정보]`
- **운영 특성**: 매일 아침 **08:00경** 당일 가파도·마라도 운항 여부(정상운항 / 기상악화 결항)를 명확히 갱신합니다. (단, `wonderfulis.co.kr`은 `ALLOWED_DOMAINS`에 없으므로 직접 크롤링 시 추가 필요하며, 그보다 위의 **KOMSA 공식 API(`B554035`)**를 쓰는 것이 훨씬 안정적입니다.)

#### ③ 마라도 여객선 (`송악페리` — 송악산항)
- **공식 URL**: `https://www.songakferry.com`
- **운영 특성**: 매일 아침 **08:30경** 당일 운항 여부를 업데이트합니다. (모슬포 운진항과 인접해 있어 기상 결항 시 운진항 마라도 배편과 거의 동시에 통제됩니다.)

## 4. 브리핑 카드(`brief-card.js`) 반영을 위한 실용적 구현 제안

특보 브리핑 카드(`/?brief=1` → `특보` 탭)는 **운영자가 샤오홍슈에 업로드하기 위해 직접 열고 저장 버튼을 누르는 도구**입니다. 이 특성을 살리면 100% 신뢰할 수 있는 구조로 설계할 수 있습니다.

### 제안 아키텍처: "자동 판별(API + 해상특보 규칙) + 운영자 1클릭 오버라이드"

1. **자동 기본값 추론**:
   - **가파도·마라도**: KOMSA API(`B554035/ferry-route-info-v4`)에서 `모슬포-가파도`, `모슬포-마라` 상태를 조회하여 자동 세팅.
   - **우도 (성산포항)**: 이미 `loadAlerts()`에서 파싱한 기상청 특보(`t3`)에 **`풍랑주의보` 또는 `풍랑경보`가 `제주도앞바다(동부앞바다)` 또는 `전해상`에 발효 중**이면 법규상 도선 출항이 불가능하므로 자동으로 **`停航 (풍랑특보 통제)`**로 세팅합니다.
   - 만약 해상 풍랑특보는 없는데 육상 강풍주의보만 있는 애매한 날에는 기본값을 **`待定 (당일 아침 터미널 확인)`**으로 둡니다.
2. **운영자 컨트롤 바(`bc-controls`)에 배편 상태 토글 추가**:
   - 우도는 공식 API가 없으므로, 운영자가 카드를 저장하기 직전 화면 하단 컨트롤 바에서 **우도·가파도·마라도 상태를 클릭 한 번으로 `[정상(正常) / 결항(停航) / 미정(待确认) / 숨김]` 전환**할 수 있게 작은 셀렉트(또는 칩 버튼)를 둡니다.
   - 이렇게 하면 API 지연이나 우도 현장 돌발 결항 시에도 코드 수정 없이 1초 만에 정확한 카드를 뽑아낼 수 있습니다.

### 브리핑 카드(`bc-alertcard`) 내 표시 시안 (중국어)
