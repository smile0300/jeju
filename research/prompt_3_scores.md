# 3단계: 지도·식당 앱 점수 모으기

`research/approved_all.csv`에 있는 장소마다 아래 앱에서 **평점과 평가 수**를 찾아 CSV 하나로 저장한다.
`approved_all.csv`는 제주 거주자가 직접 고른 곳이다. 이 파일에 없는 곳은 조사하지 않는다.

## 이 자료의 쓰임

중국인 여행객에게 장소를 추천할 때 "여러 앱에서 평가가 어떤지"를 함께 보여 주기 위한 자료다. 틀린 점수는 가게를 잘못 소개하는 결과가 되므로, **직접 확인한 값만** 적는다.

## 조사할 곳

| 앱 | 적을 값 | 비고 |
|---|---|---|
| 카카오맵 | 평점(5점 만점), 후기 수 | 장소 페이지에 보이는 값 |
| 구글맵 | 평점(5점 만점), 평가 수 | 장소 페이지에 보이는 값 |
| 티맵 | 평점, 후기 수 | 없으면 비운다 |
| 다종뎬핑(大众点评) | 평점, 후기 수 | 한국 가게는 없는 경우가 많다. 없으면 비운다 |

## 지켜야 할 규칙

1. **같은 가게인지 먼저 확인한다.** 이름이 같거나 비슷한 다른 가게가 많다. 앱의 주소가 `approved_all.csv`의 `주소_ko`와 같은 동(洞)·리(里)까지 맞을 때만 값을 적는다. 맞지 않으면 그 앱 칸을 모두 비우고 `메모`에 `주소 불일치`라고 적는다.
2. **페이지에서 실제로 읽은 값만 적는다.** 검색 결과 요약이나 기억에 의존하지 않는다. 읽지 못했으면 비운다. 추측하거나 평균을 내서 채우지 않는다.
3. **접속이 막히면 멈춘다.** 로그인 요구, 자동입력 방지 화면, 접속 차단이 나오면 우회하려고 하지 말고 그 앱은 `차단`이라고 적은 뒤 다음 앱으로 넘어간다. 로그인이 필요한 앱에 계정을 만들거나 로그인하지 않는다.
4. **앱 사이에 간격을 둔다.** 한 앱에 연속으로 요청을 보낼 때는 한 곳당 최소 3초 간격을 둔다. 같은 앱에서 3번 연속 차단되면 그 앱 조사는 중단하고 나머지 장소는 `차단`으로 적는다.
5. 평가 수가 1~4개뿐인 값은 신뢰하기 어려우니 그대로 적되 `메모`에 `표본 적음`이라고 쓴다.
6. `research` 폴더 밖의 파일은 읽지도 고치지도 않는다. 결과 파일 하나만 만든다.

## 출력

파일: `research/scores_all.csv` (UTF-8, 첫 줄은 아래 헤더 그대로). 값에 쉼표가 있으면 큰따옴표로 감싼다.

```
이름_ko,주소_ko,카카오_평점,카카오_후기수,카카오_링크,구글_평점,구글_평가수,구글_링크,티맵_평점,티맵_후기수,다종뎬핑_평점,다종뎬핑_후기수,다종뎬핑_링크,확인일,확인방법,메모
```

| 칸 | 작성법 |
|---|---|
| 이름_ko, 주소_ko | `approved_all.csv`의 값을 그대로 옮긴다 |
| *_평점 | 5점 만점 숫자(예: `4.3`). 다종뎬핑이 10점제나 다른 척도면 원래 값을 적고 `메모`에 척도를 쓴다 |
| *_후기수, *_평가수 | 숫자만 |
| *_링크 | 값을 읽어 온 그 장소 페이지 주소 |
| 확인일 | 조사한 날짜 (YYYY-MM-DD) |
| 확인방법 | `페이지 직접 확인` / `검색 결과 요약` / `일부만 확인` 중 하나. 값을 읽은 방식 그대로 쓴다 |
| 메모 | `주소 불일치`, `차단`, `표본 적음`, `해당 앱에 없음` 등 |

앱에 가게가 아예 없으면 그 앱 칸은 비우고 `메모`에 `해당 앱에 없음`이라고 쓴다.

## 끝나면

아래 세 가지를 알려 준다.

1. 앱별로 값을 찾은 곳이 몇 곳이고, 차단된 앱이 있었는지
2. 주소가 맞지 않아 비워 둔 곳
3. 이름이 비슷한 다른 가게와 헷갈릴 만했던 곳
