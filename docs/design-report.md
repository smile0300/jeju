# jeju-live.com 디자인 진단 리포트

- **점검일**: 2026-08-21
- **대상**: https://jeju-live.com — 홈 / 天气预报 / 汉拿山 / 机场信息 / 失物招领
- **관점**: 프로덕트 디자이너 (색상 · 타이포 · 레이아웃/배열 · 아이콘 시스템 · 접근성)
- **방법**: Playwright 실렌더링(데스크톱 1440 / 모바일 390), CSS 커스텀 프로퍼티 덤프, 컴퓨티드 스타일 집계, WCAG 대비율·터치타겟 실측

---

## 총평

**디자인 토큰은 잘 설계돼 있는데, 화면이 그 토큰을 안 쓰고 있습니다.**

`:root`에는 Toss 계열의 완성도 높은 시스템(`#3182F6` / `#191F28` / `#8B95A1` / `#F2F4F6`, 4단계 라벨 위계, 11단계 타입 스케일, 6단계 radius, 4단계 shadow, `--touch-target: 44px`)이 정의돼 있습니다. 그런데 실제 렌더링된 화면에서는 **한 페이지에 radius 9종, shadow 8종, 폰트 사이즈/굵기 조합 18종 이상**이 나오고, 토큰에 없는 색(`rgb(57,57,57)`, `rgb(0,0,0)`, Tailwind 팔레트)이 상시 섞여 있습니다.

즉 이 사이트의 문제는 "디자인 감각"이 아니라 **시스템 집행(enforcement)의 부재**입니다. 고쳐야 할 대상은 개별 화면이 아니라 토큰과 컴포넌트 계층입니다.

두 번째 축은 **정보 설계**입니다. 이름이 "LIVE"인데 홈에는 실시간 데이터가 한 줄도 없고(런처 아이콘 9개만 존재), 공항 페이지는 이미 착륙한 새벽 항공편이 최상단을 차지합니다. 실시간성이 서비스의 핵심 가치인데 레이아웃이 그걸 표현하지 않습니다.

| 영역 | 심각도 | 핵심 문제 |
|---|---|---|
| 색상 시스템 | 🔴 High | 3개 팔레트(Toss/iOS/Tailwind) 동시 사용, 시맨틱 토큰 값 충돌 |
| 정보 설계 | 🔴 High | 홈에 실시간 데이터 0개, 공항 목록에 "지금" 기준점 없음 |
| 접근성 대비 | 🔴 High | 핵심 텍스트 다수 1.8~3.0:1 (WCAG AA 4.5:1 미달) |
| 레이아웃/컨테이너 | 🟠 Medium | 페이지마다 다른 max-width, 데스크톱 대응 부재 |
| 타이포 스케일 | 🟠 Medium | em 중첩으로 13.12 / 15.2 / 18.4px 같은 소수점 사이즈 양산 |
| 아이콘 시스템 | 🟠 Medium | Phosphor 4 weight + 이모지 + 3D 일러스트 혼용 |
| 터치 타겟 | 🟡 Low | 19 / 32 / 39px 요소 존재 (토큰은 44px 정의) |

## 1. 색상 — 팔레트가 3개 겹쳐 있습니다

### 1-1. 🔴 시맨틱 토큰끼리 값이 충돌

같은 의미에 서로 다른 색이 두 벌 정의돼 있습니다.

| 의미 | 플랫 토큰 | 그라디언트 토큰 | 상태 |
|---|---|---|---|
| success | `#12B886` (Toss green) | `#34C759` (iOS green) | ❌ 불일치 |
| warning | `#FFA94D` | `#FF9500` | ❌ 불일치 |
| danger | `#FA5252` | `#FF3B30` | ❌ 불일치 |

배지는 `#12B886`, 그 옆 버튼은 `#34C759` 그라디언트가 되는 구조입니다. 사용자는 "같은 초록인데 미묘하게 다른 두 색"을 보게 되고, 이건 정확히 브랜드가 아마추어처럼 보이는 지점입니다.

**개선안**
- `--success/--warning/--danger`를 **단일 소스**로 확정(Toss 계열 `#12B886`/`#FFA94D`/`#FA5252` 권장 — 이미 배지에서 더 많이 쓰임)
- 그라디언트 토큰은 해당 플랫 토큰에서 파생(`linear-gradient(135deg, var(--color-green), color-mix(in srgb, var(--color-green) 85%, black))`)
- iOS 계열 값(`#34C759`, `#FF9500`, `#FF3B30`)은 전면 삭제

### 1-2. 🔴 토큰에 없는 색이 상시 사용 중

한 페이지 실측 집계:

| 실제 사용 색 | 사용 횟수 | 문제 |
|---|---|---|
| `rgb(57, 57, 57)` | 50 | 텍스트색인데 `--label-primary(#191F28)` 아님 |
| `rgb(0, 0, 0)` | 16 | 순수 검정 — 토큰 어디에도 없음 |
| `rgba(0,0,0,.54)` | 14 | 머티리얼 계열 잔재 |
| `rgb(136, 19, 55)` | 11 | 출처 불명 |
| `rgb(234,88,12)` / `rgb(5,150,105)` / `rgb(245,158,11)` | — | Tailwind orange-600 / emerald-600 / amber-500 |
| `rgb(255, 36, 66)` (LIVE 배지) | 5 | `--color-danger(#FA5252)` 아님 |

**배경색은 더 심각합니다.** 거의 구분되지 않는 회색 3종이 동시에 깔려 있습니다.

- `#F8FAFC` (Tailwind slate-50) — 41회
- `#F2F4F6` (`--bg-secondary`) — 40회
- `#F8F9FA` (`--bg-grouped`) — 34회

세 색의 차이는 육안으로 거의 안 보이지만, 카드가 인접했을 때 **의도하지 않은 경계선**을 만듭니다. 실제로 날씨 페이지 콘텐츠 하단과 푸터 사이에 정체불명의 회색 띠가 보이는 원인이 이것입니다.

**개선안**
- 페이지 배경은 `--bg-grouped` **하나로 통일**, 카드는 `#FFFFFF` 고정 — 회색 레벨은 2단계면 충분
- 하드코딩 색 전수 치환: `#393939`·`#000` → `--label-primary`, Tailwind 색 → 대응 시맨틱 토큰
- Stylelint에 `declaration-property-value-allowed-list` 규칙을 걸어 **CSS에 raw hex/rgb 작성 자체를 CI에서 차단**. 이걸 안 하면 아무리 정리해도 3개월 뒤 원상복귀합니다.

### 1-3. 🟠 의미색이 과잉이라 색이 정보를 잃었습니다

날씨 페이지 시간별 예보 한 테이블 안에:
- 강수확률 = 파랑 / 기온 = 검정 / 풍속 = 주황·회색 혼용 / 최고기온 = 빨강 / 최저기온 = 파랑

**주황이 "바람 세기"이면서 동시에 다른 화면에서는 "경고/부분통제"**입니다. 색 하나가 두 개 의미를 가지면 색은 더 이상 신호가 아니라 장식입니다.

**개선안**
- 색을 **상태(status)에만** 예약: 초록=정상, 주황=주의, 빨강=위험/지연, 파랑=인터랙티브. 그 외에는 전부 중립 회색 + 굵기로 위계 표현
- 수치 강조는 색이 아니라 **font-weight + 크기**로 (최고기온만 `600`, 최저기온은 `--label-secondary`)
- 풍속의 주황은 삭제하고, 실제 위험 임계값(예: 10m/s 초과)에서만 주황 적용 — 그래야 주황이 의미를 되찾습니다

### 1-4. 🔴 대비율 미달 (WCAG AA)

| 요소 | 크기 | 대비율 | 기준 | 판정 |
|---|---|---|---|---|
| 홈 태그라인 `济州旅行·实时情报·一站搞定` | 15.2px | **1.90** | 4.5 | ❌ 거의 안 보임 |
| SEO 설명문 `济州岛实时天气预报…` | 12px | **1.80** | 4.5 | ❌ |
| `寻物动态` 배지 (흰 글자/주황) | 12px | **1.90** | 4.5 | ❌ |
| `SOON` 배지 | 11px | **2.01** | 4.5 | ❌ |
| 비활성 탭 `出发航班` | 15px | **2.46** | 4.5 | ❌ |
| 비활성 탭 `历史天气` | 15.2px | **2.76** | 4.5 | ❌ |
| `汇总一览` 버튼 | 12.5px | **2.88** | 4.5 | ❌ |
| 활성 탭 `到达航班` (파랑/연파랑) | 15px | **3.71** | 4.5 | ❌ |
| `LIVE` 배지 | 11.2px | **3.76** | 4.5 | ❌ |
| 언어 스위처 `KR` | 11px | **3.04** | 4.5 | ❌ |

특히 **비활성 탭 2.4~2.8:1**은 "누를 수 있는 탭"이 아니라 "비활성화된 버튼"으로 읽힙니다. 出发航班(출발 항공편)은 도착만큼 중요한 기능인데 UI가 그걸 숨기고 있는 셈입니다.

**개선안**
- 보조 텍스트 최소색을 `--label-secondary(#8B95A1)` → **`#6B7684` 수준으로 상향**, `--label-tertiary`는 장식용으로만 제한하고 본문에는 금지
- 배지 흰 글자는 배경을 한 단계 어둡게(주황 `#FFA94D` → `#E8590C` 계열), 또는 **연한 배경 + 진한 글자** 방식으로 전환 (`bg: rgba(255,169,77,.14)` + `color: #C2410C`)
- 비활성 탭은 opacity 대신 **`#4E5968` 고정**, 활성 탭은 색 대신 **밑줄 인디케이터 + `600` 굵기**로 구분 → 색맹 사용자에게도 동작
- 타깃 사용자가 **야외에서 직사광선 아래 휴대폰**을 본다는 점을 고려하면 AA는 최소선이고 AAA(7:1)를 지향해야 합니다

## 2. 타이포그래피 — 스케일이 무너져 있습니다

### 2-1. 🟠 소수점 폰트 사이즈 양산

토큰은 `2.125rem / 1.75rem / 1.375rem …` 로 깔끔한데, 실제 렌더링 값은:

`13.12px` · `13.6px` · `14.08px` · `14.4px` · `15.2px` · `17.6px` · `18.4px` · `18.9px`

이건 **`em` 단위를 중첩해서** 쓴 결과입니다(`0.8em` 안의 `0.8em`). 한 페이지에서 **사이즈/굵기 조합 18종 이상**이 나옵니다. 중국어·한국어 CJK 폰트는 소수점 픽셀에서 힌팅이 깨져 라틴 폰트보다 훨씬 흐릿하게 보입니다.

**개선안**
- `em` 기반 폰트 사이징 전면 폐기 → **`rem` 토큰만 사용**
- 실사용 스케일을 **6~7단계로 압축**: 34 / 22 / 17 / 15 / 13 / 11px
- 굵기는 **400 / 600 / 700 3종만** (현재 400·600·700·800 혼재, `800`은 CJK에서 획이 뭉갬)
- `font-feature-settings: "tnum"` 을 기온·시각·항공편명 등 **모든 수치에 적용** — 지금 시간별 예보 테이블에서 숫자 폭이 흔들려 열 정렬이 미세하게 어긋납니다

### 2-2. 🟠 섹션에 제목이 없습니다

날씨 페이지는 카드 4개(실시간 / 시간별 / 10일 / 대기질)가 **제목 없이** 연속됩니다. 사용자는 표를 해독해서 이게 무슨 데이터인지 역추론해야 합니다.

**개선안**
- 모든 섹션 카드 상단에 **17px/600 제목 + 우측 보조 액션** 패턴 고정 (`24小时预报`, `未来10天`, `空气质量`)
- 카드 사이 간격을 `--space-4(16px)`로 통일하고, **제목이 그룹의 시작점**임을 여백으로 명확히(제목 위 24px / 아래 12px)

## 3. 레이아웃 · 배열 — 페이지마다 규칙이 다릅니다

### 3-1. 🟠 컨테이너 폭이 페이지마다 제각각

1440px 데스크톱 실측:

| 페이지 | 콘텐츠 폭 | 결과 |
|---|---|---|
| 홈 | 약 **594px** 중앙 정렬 | 좌우 420px씩 빈 공간, 화면의 60%가 공백 |
| 汉拿山 | 약 **1160px** 풀블리드 | 카드가 과도하게 늘어나 텍스트 한 줄 + 여백 |
| 天气 / 失物招领 | **600~640px** | 홈과도, 한라산과도 다름 |

같은 사이트를 이동하는데 **콘텐츠 폭이 매번 점프**합니다. 브랜드 일관성이 가장 크게 무너지는 지점입니다.

**개선안**
- 전역 레이아웃 프리미티브 도입: `--container-narrow: 640px`(폼/리스트) / `--container-wide: 1120px`(그리드/대시보드) 두 종류만
- 모든 페이지가 **동일한 헤더·컨테이너 셸(shell)을 공유**하도록 리팩터링 — 지금은 페이지마다 레이아웃을 따로 짠 흔적이 명확합니다

### 3-2. 🟠 데스크톱이 "늘어난 모바일"입니다

한라산 데스크톱에서 `预约汉拿山` 버튼이 **580px 폭**으로 뻗어 있고, 상태 히어로 카드는 텍스트가 좌측 1/4에만 있고 나머지 3/4이 빕니다. 홈은 반대로 1440px 화면에서 594px 칼럼만 쓰고 데이터는 0개입니다.

**개선안**
- 버튼에 `max-width: 240px` 상한 — 액션 버튼은 절대 컨테이너 폭을 따라가면 안 됩니다
- 데스크톱(≥1024px)에서 **2컬럼 대시보드**로 전환: 좌측에 날씨·항공, 우측에 한라산 CCTV·분실물 최신 — 세로 스크롤이 줄고 "Live" 정체성이 살아납니다
- 히어로 카드는 우측 여백에 **보조 지표(기온/풍속/가시거리)를 배치**해 빈 공간을 정보로 전환

### 3-3. 🟠 그리드 고아(orphan) 카드

- 한라산 등산로 7개 → 3×3 그리드에서 마지막 줄에 **1개만 덩그러니** 남음
- 홈 아이콘 9개 → 데스크톱에서 5+4 로 깨짐 (모바일 3×3은 양호)

**개선안**
- 등산로는 카드 그리드가 아니라 **세로 리스트**가 적합합니다. 항목이 "이름 + 상태 + 거리 + 소요시간" 4속성인데, 카드에 넣으니 중앙정렬로 흩어져 **세로 비교(스캔)가 불가능**합니다. 좌측 상태 점 · 중앙 이름/거리 · 우측 상태 배지의 리스트 행으로 바꾸면 7개를 한눈에 비교 가능
- 홈은 데스크톱에서 컬럼 수를 **3 또는 4의 배수**로 고정하거나, 마지막 줄을 좌측 정렬로 흘림

### 3-4. 🟠 정렬 축이 흔들립니다

한라산 카드는 배지·이름·거리가 **모두 중앙정렬**입니다. 중앙정렬은 항목이 3개 이상 세로로 쌓이면 **좌측 시작점이 매 줄 달라져** 눈이 지그재그로 움직입니다. CJK 텍스트는 글자폭이 균일해서 이 문제가 라틴보다 더 두드러집니다.

**개선안**: 리스트·카드 내부 텍스트는 **전부 좌측 정렬**. 중앙정렬은 빈 상태(empty state)와 히어로 타이틀에만 허용.

## 4. 아이콘 · 그래픽 — 4개 시스템이 섞여 있습니다

한 페이지에서 확인된 아이콘 소스:

| 소스 | 사용 |
|---|---|
| Phosphor **Duotone** | 111회 (주력) |
| Phosphor **Fill** | 9회 |
| Phosphor **Regular** | 6회 |
| Phosphor **Bold** | 3회 |
| 이모지 (📖 ℹ️ 🔍 📢) | 失物招领 안내문 전반 |
| 3D 스큐어모픽 날씨 일러스트 | 天气 페이지 |

Duotone은 채도가 낮고 부드러운데 Fill은 단단합니다. 여기에 3D 날씨 아이콘과 이모지가 붙으면 **한 화면에 4가지 시각 언어**가 공존합니다. 홈 런처 아이콘이 파랑/초록/보라/분홍/빨강/주황으로 제각각인 것도 같은 문제 — 아이콘 색이 카테고리 의미를 담지 않고 그냥 알록달록합니다.

**개선안**
- **Phosphor Duotone 단일 weight로 통일**, 크기는 20/24/32px 3종만
- 이모지는 **전면 제거** — 플랫폼(Android/iOS/Windows)마다 다르게 렌더되고 스크린리더가 "책 이모지"라고 읽습니다
- 3D 날씨 일러스트는 유지하되 **날씨 조건 표현 전용**으로 격리(다른 곳에 3D 금지). 유지한다면 8종(맑음/구름조금/흐림/비/눈/뇌우/안개/황사) 세트를 동일 작가 스타일로 갖춰야 합니다
- 홈 런처 아이콘은 **단색(`--label-primary`) + 배경 틴트**로 통일하거나, 색을 쓴다면 **카테고리 = 색** 규칙을 문서화(자연=초록, 이동=파랑, 이벤트=보라, 도움=주황)

## 5. 페이지별 개선 포인트

### 5-1. 홈 — "LIVE"인데 실시간 데이터가 없습니다

현재 구조: 대형 워드마크 → 저대비 태그라인 → 분실물 티커 → 아이콘 9개 → 푸터. 화면 상단 40%를 로고가 차지하고, 실시간 정보는 **한 줄도 없습니다.**

**개선안**
- 워드마크를 상단 헤더로 축소(높이 56px)하고, **첫 화면에 라이브 요약 카드** 배치: 현재 기온·한라산 통제 여부·다음 도착 항공편·오늘 등록된 분실물 수. 이게 이 서비스의 유일한 차별점입니다
- 아이콘 9개 중 4개가 `SOON`(미출시)입니다. **미출시가 44%를 차지하는 그리드**는 서비스가 비어 보입니다 → SOON 항목은 하단 별도 섹션("即将上线")으로 분리하고 상단은 동작하는 5개만
- `SOON` 배지가 회색이라 카드 전체가 비활성처럼 보이는데, 정작 카드는 눌립니다. 배지를 지우거나 카드에 실제 `opacity`/`cursor: not-allowed`를 주어 **시각과 동작을 일치**시켜야 합니다
- 하단 고정 **탭바(날씨/항공/한라산/분실물/더보기)** 도입 — 현재 페이지 간 이동이 "뒤로가기 → 홈 → 재선택"뿐이라 매 이동이 3탭입니다
- 모바일에서 **초록 채팅 FAB가 푸터의 `客服中心` 버튼을 물리적으로 가립니다** (390px 실측). FAB에 `bottom` 여백을 주거나 푸터 진입 시 숨김 처리

### 5-2. 天气 — 빈 데이터가 "정상"처럼 보입니다

- 대기질 게이지(PM10/PM2.5/O3)가 **값 없이 `--`인데 링은 초록 풀컬러**입니다. 초록은 "좋음"을 뜻하므로 **데이터 없음이 좋음으로 오독**됩니다. → 빈 상태는 회색 점선 링 + "데이터 없음" 명시
- 시간별 예보 테이블이 우측에서 **잘려 나가는데 스크롤 가능하다는 신호가 없습니다**. → 우측 페이드 그라디언트 + 첫 열(`시간`) sticky 고정
- 10일 예보가 5×2 그리드인데 **날짜가 좌→우로 흐르다 줄바꿈**되어 시간 흐름이 끊깁니다. → 가로 스크롤 1줄 또는 세로 리스트로 변경(세로가 비교에 유리)
- 오늘 카드만 파란 테두리인데 나머지와 배경이 같아 강조가 약합니다 → 배경 `--accent-subtle` 채우기

### 5-3. 机场信息 — 시간 축에 "지금"이 없습니다

30편이 **구분 없는 단일 목록**으로 나열되고, 오후 2시에 접속했는데 **최상단이 06:05 이미 착륙한 항공편**입니다. 초록 `已到达` 배지가 13번 반복되어 시각적 소음만 만들고, 정작 사용자가 볼 다가오는 항공편은 스크롤 한참 아래에 있습니다.

**개선안**
- **"현재 시각" 구분선**을 삽입하고 기본 스크롤 위치를 거기로 (완료 항공편은 상단에 접어두기)
- `即将抵达 / 已到达` 섹션 헤더로 그룹화, 완료 건은 **배지 대신 행 전체를 60% 밝기**로 낮춤 — 배지 반복보다 훨씬 조용하고 명확
- 지연 항공편만 주황/빨강 → 색이 "예외"에만 쓰여야 눈에 띕니다
- 항공사 **로고 표시** — 중국인 여행객에게 `真航空`/`易斯达航空` 같은 한국 LCC 한자 표기는 인지도가 낮습니다. 로고가 텍스트보다 빠르게 식별됩니다
- 편명 검색 필드 추가(30편 목록에서 특정 편을 찾는 유일한 방법이 지금은 눈으로 훑기입니다)

### 5-4. 失物招领 — 안내문이 결과를 밀어냈습니다

첫 화면이 **사용 설명서**입니다. 필터 → CTA 버튼 → 탭 → 안내 카드까지 **컨트롤 4겹**을 지나야 실제 데이터가 나옵니다. 상단에는 내용 없는 주황색 빈 띠도 렌더됩니다.

**개선안**
- 안내문은 **접이식(accordion) 기본 닫힘** 또는 도움말 아이콘 뒤로 → 첫 화면은 **검색 결과**여야 합니다
- 컨트롤 4겹 → **필터 바 1줄(지역·분류·날짜 칩) + 결과**로 압축, `登记并请求追踪` CTA는 결과 하단 또는 FAB로 이동
- 상단 빈 주황 띠 제거(콘텐츠 없으면 렌더 자체를 스킵)
- 이모지 헤딩(📖 ℹ️)을 Phosphor 아이콘으로 교체

### 5-5. 汉拿山 — 가장 완성도 높지만 그리드가 임의적

CCTV 5개가 **1개 대형 + 2 + 2** 배치인데, 왜 첫 번째가 큰지에 대한 근거가 없습니다(중요도 표시도 아님).

**개선안**: 균등 2열 그리드로 통일하거나, 대형 슬롯을 **"현재 통제 중인 구간의 CCTV"**에 동적 할당해 크기에 의미를 부여. `LIVE` 배지는 대비 3.76 → 배경을 `#E03131`로 낮추고 점 애니메이션 유지.

## 6. 접근성

### 6-1. 🟡 터치 타겟이 토큰 기준 미달

`--touch-target: 44px` 토큰이 정의돼 있는데 실제로는:

| 요소 | 실측 높이 |
|---|---|
| 푸터 `使用条款` / `隐私政策` | **19px** |
| 푸터 `小红书` / `微信` / `链接分享` / `客服中心` | **32px** |
| `预约汉拿山` / `汉拿山公告` | **39px** |

**개선안**: 시각적 크기는 유지하되 `::before` 확장 또는 패딩으로 **히트 영역만 44px 확보**. 특히 푸터 링크 19px는 이동 중 한 손 조작에서 거의 못 누릅니다.

### 6-2. 색에만 의존하는 상태 표현

`正常运营`(초록) / `部分管制`(주황)은 색+텍스트라 양호하지만, 항공 지연·기온 고저는 **색만으로** 구분됩니다. 적록색약 사용자에게 정보가 사라집니다.

**개선안**: 상태 배지에 아이콘 병기(✓ / ! / ×), 기온은 ↑↓ 화살표 추가.

### 6-3. 다국어 폰트 스택

`font-family`가 `-apple-system` 우선이라 Android/Windows 중국어 사용자는 **폴백 폰트로 렌더**됩니다. 타깃이 중국인 관광객(대부분 Android + 微信 인앱 브라우저)임을 감안하면 우선순위가 뒤집혀 있습니다.

**개선안**: `-apple-system, "PingFang SC", "HarmonyOS Sans SC", "Noto Sans SC", "Microsoft YaHei", sans-serif` 로 **간체 중문 폰트를 명시적으로 앞쪽에** 배치. 微信 인앱 브라우저에서의 실제 렌더 확인 필수.

## 7. 실행 로드맵

### P0 — 신뢰도 직결 (1~2주)
1. 시맨틱 컬러 토큰 충돌 해소 (success/warning/danger 단일화)
2. 대비율 AA 미달 전수 수정 — 특히 비활성 탭·배지·태그라인
3. 대기질 `--` 빈 상태를 초록 게이지에서 **중립 회색**으로 (오독 방지)
4. 공항 목록에 "현재 시각" 기준점 + 완료/예정 그룹화
5. 모바일 FAB ↔ 푸터 버튼 겹침 수정

### P1 — 시스템 정리 (3~4주)
6. 하드코딩 색 전수 토큰 치환 + **Stylelint CI 차단 규칙**
7. `em` 폰트 사이징 폐기, 타입 스케일 6단계로 압축, 굵기 3종 제한
8. radius 9종 → 4종 / shadow 8종 → 3종 정리
9. 전역 컨테이너 프리미티브 도입, 모든 페이지 동일 셸 공유
10. Phosphor Duotone 단일화 + 이모지 제거
11. 섹션 카드 제목 패턴 전 페이지 적용
12. 터치 타겟 44px 확보

### P2 — 구조 개선 (5~8주)
13. 홈을 런처 → **라이브 대시보드**로 재설계, SOON 항목 분리
14. 하단 탭바 도입
15. 데스크톱 2컬럼 레이아웃
16. 한라산 등산로 카드 → 스캔 가능한 리스트
17. 분실물 안내문 접기, 첫 화면을 결과로
18. 간체 중문 폰트 스택 정비 + 微信 인앱 브라우저 실기기 검증
